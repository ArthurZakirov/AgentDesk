# ⏱️ Effort and scope checkpoints

Check effort before substantial work and when focused technical problem-solving becomes a repeated struggle. This applies across types of deliverables, not just code or tests.

| When | Then |
| --- | --- |
| **Before substantial work:** The agent is about to start a time-consuming or review-heavy step. | Run the **effort check** below before committing to the step; no prior evidence of an overrun is required. |
| **During focused technical problem-solving:** Arthur is actively trying to understand or resolve a technical problem and repeatedly asks for explanations, code walkthroughs, visualizations, simplifications, or reviews without reaching stable understanding. | Before another explanation or implementation attempt, run the **effort check** using actual effort, review friction, and remaining work. A single ordinary clarification does not activate this check. |

**Effort check** — keep the investigation proportionate:

1. **Find the baseline.** Inspect the controlling ticket, specification, refinement notes, or recorded decision for the agreed effort and remaining budget. Convert story points to hours only if the team's convention supports it; never invent a baseline.
2. **Estimate the remainder.** Identify the work and existing reusable approaches. Include execution, verification, human understanding/review, and coordination where applicable, accounting for work already completed. Use a plausible range rather than spurious precision.
3. **Compare.** Does the estimated remaining effort materially exceed the remaining agreed budget? A large diff, difficult task, or single clarification is not sufficient evidence by itself.
4. **Act.** If yes, pause the affected work and tell Arthur concisely: agreed expectation, extra work and cost, and the decision needed from the accountable scope owner. If the baseline is unavailable, flag what is missing and clarify it before a substantial commitment. Otherwise proceed.

For company or shared work, Arthur's request to continue does not authorize unplanned scope or effort: seek approval from the manager, accountable scope owner, or explicitly delegated authority. A technical expert can identify a simpler approach but does not authorize scope without delegation. While waiting, continue only independent, already authorized work. For private experiments that do not affect commitments or shared systems, Arthur can approve the time box himself.
